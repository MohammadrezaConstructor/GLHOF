# LLMSR Procurement Ranking Experiments

Research code for constructing historical supplier features, running
deterministic procurement-ranking experiments, evaluating scenario sensitivity,
and testing LLM-assisted advisory and evidence-extraction workflows.

This public package is code-first. Source datasets, derived databases, model
artifacts, API checkpoints, and generated reports are intentionally excluded
because they are large and may have separate access or redistribution terms.

## Requirements

- Python 3.10 or newer
- Sufficient disk and memory for the selected dataset and experiment
- An OpenAI API key only for scripts whose names contain `openai` or for
  experiments explicitly run with `--run-api`

Create an isolated environment and install the dependencies:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On macOS or Linux:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Raw and derived data should remain untracked. If the underlying datasets are
publicly redistributable, publish them separately in a data repository and add
their download URLs, versions, checksums, and licenses here.

## Running experiments

Many scripts accept `--root .` and perform schema/path validation before doing
substantive work. A representative non-API preflight is:

```bash
python scripts/run_r22_preflight.py --root .
```

See [`scripts/README.md`](scripts/README.md) for the recommended order and exact
commands for the Reviewer 2.2 experiment suite.

API-backed scripts read credentials from the environment. Never place a key in
source code or commit a `.env` file. In PowerShell:

```powershell
$env:OPENAI_API_KEY = "your-key"
```

API calls can incur cost. Use preparation/check modes first and enable
`--run-api` only after reviewing the generated inputs and configured model.

## Reproducibility notes

- Observed awardees are treated as historical reference outcomes, not as
  normatively optimal suppliers.
- Historical comparison sets are not necessarily observed bidder pools.
- Proxy subgroup sensitivity is not a complete fairness audit.
- Supervised baselines may reproduce historical patterns.
- Controlled benchmarks should not be presented as real-world applicability
  results.
- Freeze prompts, mappings, model identifiers, and settings before final runs.

## Publishing checklist

Before making the GitHub repository public:

1. Choose and add a `LICENSE` file.
2. Add the dataset source, access instructions, and redistribution terms.
3. Add author names, affiliation, contact information, and citation metadata.
4. Review the staged file list and secret scan results.
5. Create a release tag only after reproducing the reported results.
